# 验收手册

> 用途：让不读代码的人也能判断"这一步到底做完没有"。
> 每个里程碑都必须按四件事交付，缺一件视为未完成。

> **关于数字**：下面每节出现的张数/角色数，都是**写那一节时的快照**（当时库里有多少张、角色表几条）。
> 照着做验收时**以你自己的库为准**——把 `N` 换成 `/meme doctor` 报出来的数字即可。
> 唯一的权威现状写在 `05-handoff.md` 的 §0 复核快照里。

---

## 0. 交付格式（每个里程碑固定四段）

| 段 | 内容 | 谁看 |
|---|---|---|
| **① 做什么** | 一句话说明这一步让系统多了什么能力，不用技术名词 | 你 |
| **② 怎么验** | 一条可复制的命令 + 预期输出。输出对不上就是没过 | 你 |
| **③ 你世界里的变化** | 磁盘/命令/界面/数据上会多出什么 | 你 |
| **④ 怎么退** | 出问题时如何回到上一步 | 你 |

**通用规则**

1. 验收必须是一个**你能自己执行的命令**，不能是"我跑了测试通过"；
2. 预期输出要写具体（不是"应该正常"，而是"会出现 6 行，其中一行是 `library 288 个文件`"）；
3. 不通过就停下修，不往下走；
4. 每个里程碑结束时，本文的"状态板"和 README 的里程碑表必须同步更新。

## M0 · 插件装上、命令能跑 ✅

**① 做什么**
让 DSH 认识这个插件，并提供一个 `/meme` 命令。此时它还没有任何表情数据，只会"体检"。

**② 怎么验**

在 DSH 会话输入框（不是 QQ）输入：

```
/meme doctor
```

**预期输出**（当前应该正好长这样）：

```
库根目录     C:\Users\zihua\.dsh\meme-brain（尚未创建）

结论：空库，一切正常（M0 骨架只做体检，尚无内容）

✓ 体检通过
```

再输入 `/meme help` 会列出子命令。

**③ 你世界里的变化**
- 多了一个命令 `/meme`；
- 还没有任何文件、任何数据。

**④ 怎么退**

## M1 · 能读懂图片、判断重复 ✅

**① 做什么**
给系统装上"眼睛"：能打开任意格式的表情（jpg/png/gif/webp），算出它的 64 位指纹；两张图指纹接近就判为重复。**这一步是纯计算，不碰你的库、不产生任何文件。**

**② 怎么验**

打开 PowerShell，依次执行：

```powershell
cd F:\dsh-meme-brain
npm test
```

**预期输出**：最后几行是

```
ℹ tests 20
ℹ pass 20
ℹ fail 0
```

再执行（把路径换成你的 Aurabot 表情库）：

```powershell
node scripts\scan-library.mjs "$env:USERPROFILE\.dsh\plugins-data\aurabot\stickers"
```

**预期输出**：开头类似

```
文件数     291（解析成功 291，失败 0）
总体积     168.9MB，用时 5.5s，平均 19.1ms/张
格式       gif 137 / jpeg 138 / png 16
```

后面跟着 `重复簇    17` 和每组的文件列表。

**怎么判断它是对的**
- `失败 0` → 所有格式都能读（包括 WebP，这是靠 sharp 做到的）；
- 重复簇里能看到成对的、文件名不同但内容相同的图；
- 如果你记得某两张是同一张，去找它俩是否落在同一组里。

**③ 你世界里的变化**
- 没有任何文件被创建或修改；
- 只是多了三个模块和一串测试（在 `src/lib`、`test`）。

**④ 怎么退**
这一步没有副作用，不需要退。

> 为什么 M1 的验收是命令而不是按钮：这一步是"内功"，还没有用户界面。M2 起每一步都会有命令入口。

## M2 · 有了库和索引 ⏳

**① 做什么**
建立一个真正的表情库：把图片收进 `~/.dsh/meme-brain/library/`，并用一张索引表记住每张图的指纹、尺寸、状态。重复的图**在入库前**就会被拦下。

**② 怎么验**（三条，全过才算完成）

```powershell
# 1. 把现有的 Aurabot 库导入（先看会做什么，不写盘）
/meme import %USERPROFILE%\.dsh\plugins-data\aurabot\stickers --dry-run
```
预期：报告"将导入 N 张、其中重复 M 张、跳过 K 张"，且**不写任何文件**。

```powershell
# 2. 真的导入
/meme import %USERPROFILE%\.dsh\plugins-data\aurabot\stickers
```
预期：`导入完成：新增 N 张，重复 M 张，失败 0 张`

```powershell
# 3. 体检
/meme doctor
```
预期：`library 文件数` 与 `索引记录数` **两个数字相等**，`孤儿 0`，`索引缺文件 0`。

**破坏性验证**（确认 doctor 真的在工作）：
手动删掉 `~/.dsh/meme-brain/library/` 里任意一张图，再跑 `/meme doctor`。
预期：出现 `索引缺文件 1`，并提示可以 `/meme repair`。
然后跑 `/meme repair`，预期恢复为 0。

**③ 你世界里的变化**
- 出现目录 `C:\Users\zihua\.dsh\meme-brain\`，里面有 `library/` 和 `index.db`；
- 磁盘会多占一份图片（原库不动）。

**④ 怎么退**
删除 `~/.dsh/meme-brain/` 整个目录，系统回到 M1 状态（Aurabot 原库不受影响）。

## M3 · 管理命令集 ✅ 代码完成（待验收）

**① 做什么**
不用界面就能管库：列出、看单张、看重复、看待办，以及把源库里原有的名字和标签回填进来。

**② 怎么验**

```
/meme list --limit=5
```
预期：`共 275 条，显示第 1–5 条`，每条两行（md5 前缀 + 名字，尺寸/格式/状态）。**此刻名字应显示"（未命名）"**，因为导入时没带过来。

```
/meme backfill %USERPROFILE%\.dsh\plugins-data\aurabot\stickers
```
预期：`源库 N 条 · 匹配 275 条 · 更新 275 条`。再跑 `/meme list --limit=5`，名字应该出来了。

```
/meme show <列表里的 md5 前缀>
```
预期：md5 / 名字 / 标签 / 文件 / 指纹 / 状态 / 来源 / 入库时间 / 分析状态 / 库内路径。

```
/meme dupes
```
预期：`库内 N 张，未发现重复簇。`（N 以 `/meme doctor` 为准）

```
/meme todo
```
预期：`总数 275`、`未分析 275`、`未命名（回填后应为 0）`、`疑似重复 0 组`。

**通过标准**：五个命令都有合理输出；`list` 的"共 N 条"与 `/meme doctor` 的总数一致。

**③ 变化**：多了五个命令；`index.db` 里的 `name` / `tags` 被填上（这是**唯一改数据**的一步，且只填空字段）。
**④ 回退**：不需要退——名字只影响显示，`--force` 才会覆盖已有值。

## M4 · 最简界面 ✅ 代码完成（待验收）

**① 做什么**
在 DSH 侧栏加一个"表情包"入口：网格看图、点开看详情、直接改名字和标签。页面不含任何业务逻辑，全部数据来自 `/meme-brain/api`。

**② 怎么验**

1. **刷新 DSH 页面**（Ctrl+R）。
   - 侧栏出现一个"表情包"图标（笑脸方块）；
   - 若没有出现，说明客户端图需要重启 DSH 才会重建——先试 `/meme doctor`，命令正常就说明只是界面没加载。

2. 点图标 → 主区出现网格，右上角显示 `共 N 张`（N 与 `/meme doctor` 一致）。

3. 点任意一张 → 右侧出现详情：大图、名字、标签、md5、尺寸帧数、指纹、状态。

4. 把名字改成 `测试名字` → 点「保存」→ 提示"已保存"。

5. 回到输入框执行 `/meme show <那张的 md5 前缀>` → 名字应为 `测试名字`。

**通过标准**：界面上的数量与 `/meme doctor` 的总数一致；改名字后命令能读到同一个值（证明界面没有自己的数据）。

**③ 变化**
- 侧栏多一个入口；
- 多了本地 HTTP 端点 `/meme-brain/api`（仅本机可访问，非回环地址返回 403）。

**④ 怎么退**
不点它就是；页面挂掉不影响任何命令。要彻底移除界面，删掉 `package.json` 的 `dsh.client` 段即可。

## M5 · 七维分析 ✅ 代码完成（待验收）

**① 做什么**
让模型看每一张表情，给出：名字、角色、图上文字、六维分（情绪/强度/攻击/亲密/抽象/指向）、场景。

**② 怎么验**

先用 5 张试水（大约 2 次模型调用，10~20 秒）：

```
/meme analyze --limit=5
```

预期：`分析完成：成功 5 张，失败 0 张，补了 3 个名字`（补名字的数量取决于原来是不是占位名）。

然后看结果：

```
/meme list --limit=5
```
预期：原来叫「动图41」的，现在应该有「猫猫抱碗」这类真名字。

```
/meme show <其中一张的 md5 前缀>
```
预期：`评分 {"valence":...,"arousal":...}` 不再是「未分析」。

**一致性验证**（重要）：同一张再跑一次，数值应基本一致。

```
/meme analyze --limit=1 --md5=<那张的前缀> --force
/meme show <同一张>
```
预期：两次的六维数值偏差 ≤ 0.1（temperature 已设为 0）。

**③ 变化**
- 索引里多了 `score` / `scene` / `text` / `character` / `analyzed_at` / `model`
- 会产生模型调用费用（deepseek-flash，单张约 ¥0.001）
- 占位名（动图N）会被替换成真名字；已有的真名字不动（除非 `--force`）

**④ 怎么退**
分析结果不影响图片与命令的可用性；要清空可执行 `/meme analyze --reset`（M5.1 提供），或直接 `/meme rebuild` 重建（会把 name 之外的分析字段清掉）。

## M9-b · 筛选条 + 实时人工标注 + 锁定保护 ✅

**① 做什么**

三件事，互相咬合：

**1. 筛选条**（界面顶部一排带数字的按钮）

```
全部 275 │ 未分析 4  未命名 0  无标签 55  未知角色 210 │ 大肥鱼 26  龙图 21  耄耋 11  doro 6  ggbond 1
```

- 数字不写死，全部来自 Host 的 `op=facets`（界面不算数）
- 待办筛与角色筛**互斥**：点「未知角色」再点「大肥鱼」，前者自动取消
- 待办清空时会明说「这一类已经清空」，不会让你以为界面坏了

**2. 详情里实时改角色**

名字、标签之外多了「角色」输入框（带既有角色下拉提示）。保存后：

- 名字/标签/角色立刻刷新，列表和计数同时刷新
- 填的是表里没有的名字 → **自动建一条角色表项**（出处记 `ui`），并明确告诉你「角色表新增了 X」
- 填「未知」或留空 → 角色清空，**交还给模型**

**3. 锁定保护**

- 手工定过角色的条目 → `pinned = 1`，详情里显示「人工锁定中：analyze 会跳过这张」
- `/meme analyze --force` 会跳过它们；点名 `--md5` 也跳过，并告诉你原因

## M7-b / M8 · 新库接管 QQ 表情（独立模块 · 内置只停用）✅

**① 做什么**

内置表情模块用的是它自己的 `index.json` 库。这一版让**新库接管她的表情行为**，但**不顶掉内置模块**：

| | 做法 |
|---|---|
| 内置 `stickers` 模块 | **代码原样留在插件里**，只在配置里停用（`modules.stickers.enabled = false`）。插件升级照常，想退回只改这一个开关 |
| 新模块 | 独立 id **`meme-qq`**（`integrations/aurabot/meme-qq/`），不跟任何模块重名 |
| 旧的 `gif-stickers` 补录 | 逻辑并进 `meme-qq`，模块同样只停用不删 |

内置停用后，她原来靠内置模块做的三件事由 `meme-qq` 接住：

| 原来的路 | 现在 |
|---|---|
| `<sticker:标签>` → hub 调内置 `match` | `reply/items` 事件里换成我们库里的图（找不到就丢掉，和内置行为一致） |
| 自动配表情（`stickers.autoChance`） | `reply/items` 里按概率补一张，概率读原配置或模块设置 |
| 偷表情（hub 调内置 `collect`） | 自己的 `message` 监听：普通表情 + 动图（`sub_type=11`）都收 |

工具：`meme_find` / `meme_send` / `qq_send_sticker` / `qq_list_stickers` / `qq_edit_sticker` / `qq_collect_sticker` / `qq_save_sticker`。命令：`/表情 <关键词>`。

**顺带补的两条 Host 接口**（模块靠它们工作）：

```
POST /meme-brain/api?op=add&source=qq    body = 图片原始字节
     判重走 lib/pipeline.js 的 ingestBuffer —— 和目录导入是同一份规则
GET  /meme-brain/api?op=find&q=&character=&emotion=&limit=
```

**三个设计决定**：

1. **判重只有一份**：`ingestBuffer()`，目录导入和 `op=add` 共用。
2. **发送体积闸门 `maxSendMB`（默认 5MB）**：库里最大那张 9.7MB，base64 后 13MB，会被网关拒。绝大多数图可发，自动配表情只从可发的里挑。
3. **不冒充内置**：一开始我用同名 id 顶掉了内置模块，用户指出这样不好——内置应该留着、只停用。现在 `meme-qq` 完全独立，代价是上面那三条行为要自己实现（已实现并有测试）。

### 参数在哪（重要）

模块正式名字：**表情脑**（id `meme-qq`，来自 dsh-meme-brain 插件）。参数在 **面板「系统」→ 表情脑**（模块自己的独立页）。

为什么不在「表达」下——面板有两处写死：

1. `TAB_MODS = { stickers: ['stickers'] }` + `tabs.filter(t => ... .some(running))`：**「表情包」页签只在内置 `stickers` 模块运行时才存在**。内置一停，整个页签从「表达」消失。
2. `navGroupOf()`：自定义模块页只能落到「平台」（标题里有 B站/抖音 这类词）或「系统」。

所以「内置关着 + 参数在表达下」这两件事**不能同时成立**。选了内置关（库唯一），参数就只能在「系统」组。回退内置时页签会回来。

一份真相 + 一处镜像：

- **真相** = `ext['meme-qq']`（本模块设置，11 项）
- **镜像** = `config.stickers`（`enabled` 恒 false；`faces`/`collect`/`collectMode`/`fromGroups`/`fromPrivate`/`autoChance`/`maxPerHour`/`caption` 与设置同步）。hub 不看模块设置，不镜像就会出现「设置关了、hub 仍给她轻提示」这种不一致

| 参数 | 默认 | 说明 |
|---|---|---|
| 发表情 `enabled` | 开 | 关掉不发表情、不解析 `<sticker:>`（收表情不受影响） |
| 自动配表情概率 `autoChance` | 0.35 | 0 = 完全不自动配 |
| 收表情 `collect` | 开 | |
| 从群里 / 从私聊 `fromGroups` `fromPrivate` | 都开 | |
| 怎么收 `collectMode` | 全都收 | `auto` 全收 / `owner` 只听主人的 / `ask` 她挑（hub 记着+提示，她用 `qq_collect_sticker` 收） |
| 每小时最多收 `maxPerHour` | 20 | 0 = 不限 |
| 看图起名 `caption` | 开 | 唯一花钱的开关 |
| 收取上限 `maxMB` | 8 | 内置卡 1.5MB，大动图收不进来 |
| 发送上限 `maxSendMB` | 5 | 超了不发（会被网关拒），绝大多数图在 5MB 内 |
| 夹 QQ 小黄脸 `faces` | 开 | 不是本库功能，但面板页挪走后只有这里能改 |

**删掉的**：`maxLibrary`（自动删最少用的图 = 数据损失，新库不做淘汰）、v1/v2 自造的 `autoPick`/`ownerImages`。

**旧设置会自动迁过来**：模块启动时若发现 v1/v2 的遗留键（`autoPick`/`autoAnalyze`/`ownerImages`），先把当初在内置面板里设过的值搬进来，再删掉遗留键。
⚠️ `api.setConfig(patch)` 是**深合并**，删键必须用函数形式（整份替换）——这里踩过两次。

### 第一次真实使用暴露的问题（已修）

**① 同一条回复发了两张图。** 第一次私聊实测「来张生气的大肥鱼」，对方收到了**两张**。会话记录里看得清清楚楚：

```
step 1  调 meme_send {character:大肥鱼, emotion:生气}   → 发了「蓝发女仆持刀」（2.0MB）
step 2  文字「给你 气鼓鼓的」+ <sticker:生气>            → 又发了「气鼓鼓端着碗的委屈女仆」（0.5MB）
```

挑图是对的（两张都是大肥鱼），错在**同一条回复里既调工具又写了表情标签**。

**修法**：模块监听 `reply/items`（她回复拆好之后、发出去之前）。工具刚发过表情的 20 秒内、同一个聊天，把她回复里的 `<sticker:…>` 去掉；规则也改成「要发图就调一次 meme_send，调完不要再写 `<sticker:…>`」。

**② 内置工具被我顶掉了。** 内置的 `qq_collect_sticker` / `qq_save_sticker` 曾被我替换掉，而 hub 的提示词里点名让她「用 qq_collect_sticker 收表情」——她会调一个不存在的工具。已补回（`qq_collect_sticker` 按 index 从 hub 的暂存里取，`qq_save_sticker` 存这个聊天里最近那张）。

**③ 「存一下这个」结果是坏的。** 实测：私聊发一张图让她存，她回「诶 库里已经有了 那不用存」。原因是**自动收集先动手**（`collectMode=全都收` + `从私聊收` 开着），图一到就入库；`qq_save_sticker` 撞上判重，只回了「库里已经有这张了」（**没带名字**）。

**修法**：重复时带上已有那张的名字；如果她/主人顺口给了名字或标签，**把名字应用到已有那张上**（“存一下这张，叫猫猫捂嘴” 该生效，而不是白说一句）。

**④ 存图和回应被耦合了（我的设计错误）。** 我一开始做成「存完图就删掉她这轮的文字、强行塞一个表情」。用户指出原则：**存表情和对这个表情做出回应应该是两条并行、互不干扰的路径**，硬设「回」或「不回」都不对。

**修法**（把两条路彻底拆开）：
- 删掉 `saveSignal` 整套机制——**不再改写她的回复**
- 工具结果做得极淡：只回一个「好」（重复时最多带上「这张叫XX」），不给她可转述的材料
- 规则只说一句：存表情是顺手的事，别提存图、别提「库」；别人发表情时按平时习惯回，不要为了回应硬塞

实测对照（同一套代码、同一批图）：私聊那次她说了两句感想 + 甩了个表情；明月群那次她的群聊策略判定「没在聊」，于是没回。**存图都正常入库，回不回由另一条路决定**——这才是对的形态。

**⑤ 收进来不该收的图。** 实测发现库里混进了两张**游戏截图**（`副本组队招募` 921x713、`噩梦招募挂人` 878x620）。

**根因**：判定「这是不是表情」时用了「文件名像 `<32位md5>.jpg` 就当表情」——**QQ 给所有图片都起这种名字**，所以普通图和截图全被当成表情收了。

**修法**：只用确凿证据，不猜文件名——
1. 字节是真动图（GIF 多帧 / 动 WebP / APNG）→ 收（这正是内置漏掉的那一类）
2. QQ 自己标成表情段（`sub_type` = 1 收藏表情 / 7 大表情 / 11 动图表情）→ 收
3. 其余（静态 + 没被标记）→ 默认不收

**⑥ 收紧之后普通图片全都不收了。** 20:00 前后天涯群连着几张 `[图片]` 全被跳过（日志「既不是动图，也没被 QQ 标成表情段」）——一刀切的代价。

**修法**：加设置 **「普通图片也收」**（默认关），打开后只收**像表情的普通图**：
近方形（宽高比 0.6~1.7）、边长 ≤ 600、体积 ≤ 512KB —— 之前那两张截图（921×713 / 878×620）仍然会被挡住。
跳过时日志会写明 `sub_type` / 尺寸 / 大小，方便判断是「QQ 没标」还是「图不像表情」。

顺手补了库里缺的删除入口：`/meme rm <md5前缀>`（预览）→ `--yes` 才执行，**文件移到 `trash/`**（软删除，可恢复），同时删索引、记一条 `retire` 事件。那两张截图已用它对删，库里 283 → 281。

自动检查相应覆盖：存图不改写回复、工具结果不含「存/库/收进」、普通静态图不收（哪怕文件名是 md5）、标了表情段的静态图照收、真动图没标记也收、`rm` 预览不改 / `--yes` 才进 trash。
