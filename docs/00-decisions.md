# 决策记录（ADR）

每条决策记录：背景 → 决定 → 后果 → 状态。
状态取值：`已定` / `待定` / `已废弃`。

---

## ADR-0001 · 存储自管

**状态**：已定（2026-11-07）

**背景**
表情图片字节有三个潜在落点：Aurabot 的 `stickers/`、dsh-meme 的用户包、本项目自己的目录。系统必须只有一处存储，否则判重、统计、备份都会失真。

**决定**
图片字节由本项目自管：`~/.dsh/meme-brain/library/`，以 `md5` 命名的目录结构。不寄生在其它插件的数据目录里。

**依据**
1. 借 dsh-meme 的存储**并不能省掉界面开发**——它的面板看不到分数/角色/重复簇，管理台无论如何要自建；
2. 它的表只有 7 个字段（`path` 主键、单值 `tag`），装不下多维评分与角色；
3. 它上传时会改名成 `时间戳_随机`，破坏 md5 可反查；
4. 它的 `tag` 只接受 ASCII，中文分类要额外映射。

**后果**
- 需要自己实现存储层（目录 + SQLite），工作量小；
- 不再受 dsh-meme 版本/目录变化影响；
- 需要提供导入器以接收历史数据（见 ADR-0002）。

## ADR-0002 · dsh-meme 只做离线格式兼容

**状态**：已定（2026-11-07）

**背景**
社区已有 `dsh-meme` 插件（0.1.76，MIT），提供图库面板、市场、ZIP 导入导出、QQ 缩图。它确实能省事，但也有自己的数据模型与全局提示词注入。

**决定**
运行时不依赖 dsh-meme。仅在本项目实现「导入器」时兼容它的目录/包格式，用于一次性导入历史图库或未来的市场资源。

**依据**
- 它的 `dshMeme` 服务是只读的（`packs/search/pick`），写入只能走 HTTP；
- 它的 `index.db` 与本项目需要的字段不兼容；
- 它会向每个会话注入「斗图规则」系统提示词，污染与本系统无关的会话。

**后果**
- 若用户已安装 dsh-meme，建议卸载或闲置（闲置时须关闭其提示词注入）；
- 其内置 24 张、以及将来的市场包，通过导入器一次性进入本项目库。

## ADR-0003 · 判断与存储分离，索引可重建

**状态**：已定

**决定**
- **库**（`library/`）＝ 唯一事实源：图片字节 + 最小元数据；
- **索引**（`index.db`）＝ 派生数据：哈希、评分、角色、文字；
- 删除索引后，能通过扫描库重建，**不需要重新下载图片**；
- 人工标注（角色表）属于不可重建数据，单独存 `characters.json` 并纳入备份。

**后果**
索引损坏不再是事故；`doctor` 能发现并重建。

## ADR-0004 · 判重发生在入库之前

**状态**：已定

**背景**
Aurabot 现有实现是"下载 → 算 md5 → 发现已有 → 不存"，近似重复（重压/改尺寸）会漏。之前实测到一组：`摆烂摊手的厚脸皮` / `摆烂式厚脸皮`，md5 不同、dHash 距离 0。

**决定**
采集路径必须**先**调判重（精确 md5 + 三帧感知哈希），通过后才写库。判重逻辑在插件侧（Aurabot 扩展模块无依赖能力，不能自己解码）。

**后果**
- 采集多一次本地调用（~10ms，GIF 最大 ~250ms）；
- 库不会再长出重复；
- 需要提供 `--force` 通道供人工强制入库。

## ADR-0005 · 命令先行，界面是薄视图

**状态**：已定（2026-11-07）

**背景**
维护者不读前端代码。若把关键操作只做在界面里，界面出错就等于系统不可用，且无法审查。

**决定**
1. 所有管理能力先做成命令（`/meme ...`）与 HTTP 端点，界面后置；
2. 界面只做三件事：拉 JSON、渲染、发操作；不允许本地计算业务结果、不允许自己判断重复、不允许直接写数据库；
3. 任何操作都必须有"不经过界面"的路径。

**后果**
- 前端 bug 的影响半径被限制在"显示不对"；
- 里程碑里管理界面从 M3 后移到 M8；
- 界面可以被替换或暂时缺失，系统仍完整可用。

## ADR-0006 · 不向会话注入系统提示词

**状态**：已定

**背景**
dsh-meme 会向每个会话注入「斗图规则」，导致与本插件工具语义重叠，且对非表情场景是噪音。

**决定**
本插件不注册系统提示词段。能力通过工具描述与工具返回内容传达。

**后果**
模型不会"自动想起"表情系统的存在，需要在工具描述里写清楚使用时机。

## ADR-0007 · 分析模型用默认

**状态**：已定（2026-11-07）

**决定**
分析调用使用 DSH 默认模型（当前 `deepseek-flash`），配置项 `analyze.model` 留空即跟随默认；将来可填 `provider::model` 覆盖。

**依据**
- 单张约 ¥0.001，全库 177 张约 ¥0.14，成本不构成理由；
- 默认模型已验证能看图（现有起名功能在用）。

**后果**
模型升级时分析结果会变化；`items.model` 记录每条用的模型，必要时可针对性重跑。

## ADR-0008 · 评分增加"场景"维度

**状态**：已定（2026-11-07）

**决定**
在六维之外增加**场景**（多选）：`吃饭 / 工作 / 游戏 / 摸鱼 / 睡觉 / 社交 / 日常 / 无`。

**后果**
- `items` 增加 `scene` 字段（逗号分隔）；
- 检索支持按场景过滤；
- 每次分析多输出一行，token 成本增加可忽略；
- "标签"（ADR-0012）与"场景"的区别：标签是人工/历史资产，场景是模型判定，两者不合并。

## ADR-0009 · 首版做最简界面

**状态**：已定（2026-11-07）

**决定**
在 M4 交付**最简界面**：网格列表 + 详情抽屉 + 单张编辑。不做批量操作、不做导入导出、不做动图预览优化。

**依据**
命令（M3）先行使界面有可靠的后端；最简界面能让"人能用"这件事尽早成立，同时保持 ADR-0005 的约束（界面只调端点）。

**后果**
- `client.js` 从 M4 开始存在，但仍不得 import `src/lib/*`；
- 完整界面（批量、导入导出、动图、待办视图）仍留到 M9。

## ADR-0011 · 每张图有短名

**状态**：已定（2026-11-07）

**背景**
需求要求保留 `<sticker:名字>` 语法，但架构初版的 `items` 表没有名字字段——文档自相矛盾。

**决定**
`items` 增加 `name` 字段。名字**允许重复**；按名字检索时取匹配最好的一张（后续按分数排序）。

**后果**
- 模型与人都用短名引用；
- 重名不报错，但要提供 `meme doctor` 的重名统计提示；
- 名字可为空（未命名时显示 md5 前 8 位）。

## ADR-0012 · 保留标签字段

**状态**：已定（2026-11-07）

**背景**
Aurabot 现有 153 张带中文标签（委屈/卖萌/嘲讽…）。架构初版用六维分数替代了标签，导入时会丢失这批人工资产。

**决定**
`items` 保留 `tags`（逗号分隔文本）。定位为「粗分类 + 关键词搜索来源」，与六维分数并存，不互相推导。

**后果**
- 导入时中文标签原样保留；
- 检索关键词同时匹配 name / tags / text / caption；
- 标签不参与"选图打分"，只作为过滤与搜索。

## ADR-0014 · 单文件上限 16MB

**状态**：已定（2026-11-07）

**决定**
单张图片超过 16MB 直接跳过，状态 `failed`，错误码 `E_PARSE_TOO_LARGE`。

## ADR-0015 · 覆盖所有常见格式（引入 sharp）

**状态**：已定（2026-11-07）

**背景**
原方案的解码器组合（jpeg-js + pngjs + gifuct-js）**不支持 WebP**，与"尽可能覆盖所有格式"的要求冲突。

**决定**
统一使用 `sharp`（libvips）作为唯一解码后端，不再维护多解码器分支。

**实测依据**（本机验证）

| 项 | 结果 |
|---|---|
| libvips | 8.18.7 |
| 可输入格式 | jpeg, png, webp, tiff, gif, svg, heif, raw |
| 多帧 | `{animated:true}` 读 pages；`{page:n}` 取单帧 |
| 透明合成 | `flatten({background:'#fff'})` 内置 |
| 降采样 | `resize(9,8,{fit:'fill'}).greyscale().raw()` |
| 性能 | 904KB/62 帧 GIF，每帧 2ms（原 gifuct 方案最大 245ms） |

**后果**
- 引入原生依赖（约 30MB 预编译二进制），仅支持 win32-x64/linux/mac 主流平台；
- 单一代码路径，减少状态分支；sharp 不可用时插件降级为"只索引不解析"，错误码 `E_PARSE_UNSUPPORTED`；
- 不再需要 jpeg-js / pngjs / gifuct-js 三个依赖。

## ADR-0016 · 卸载 dsh-meme

**状态**：已定（2026-11-07，**修订**：原决定"留着作参考"，后改为卸载）

**背景**
最初计划保留 dsh-meme 作实现参考。但实测发现：它的 4 个工具（`send_meme` / `meme_list` / `meme_update` / `learn_meme`）对 **QQ 会话**同样是可见的，模型会直接调用。用户在群里问"有没有这张"，她回答"库里 24 张全翻了一遍"——翻的是 dsh-meme 的库，不是 Aurabot 的 153 张。

**决定**
卸载 dsh-meme（`plugin_manager remove_bundle`），本机不再保留第二套表情库与工具。

**后果**
- 已执行：profile 依赖移除，`node_modules` 清空，`application: applied`；
- 其内置 24 张官方图随插件消失（`~/.dsh/meme-packs` 从未创建，用户无自有 pack）；
- 「斗图规则」的系统提示词注入随之消失；
- 残留 `~/.dsh/dsh-expression.json`（仅设置快照，无图片）可安全删除；
- 若将来需要它的图库，可 `install_bundle dsh-meme@0.1.76` 临时装回导出（ADR-0017）。

## ADR-0019 · 同一会话不得并存第二套表情能力

**状态**：已定（2026-11-07）

**背景**
ADR-0016 的事故说明：只要另一个插件也向模型暴露"表情库"相关工具，模型就可能用错库，且错误是**静默**的——它照常给出一个看似合理的答案。

**决定**
1. 任何向模型暴露表情能力的插件，不得与本系统在同一 profile 共存；
2. 本系统接入 QQ 后（M8），Aurabot 内置表情模块必须关闭其行为（`stickers.enabled=false`），只保留对象以避免 `hub.js:616` 抛错；
3. 新装插件前检查它是否注册了表情相关工具，若有冲突先评估。

**后果**
今后"两套库"的问题不会以运行时错误出现，而是在安装阶段就被这条规则排除。

## ADR-0020 · 「是不是表情包」用模型判，不用几何猜

**背景**

收表情的判定最初用「文件名像 `<32位md5>.jpg`」，结果把 QQ 里所有图片都当表情收了（实收两张游戏截图）。收紧成「只收动图 + QQ 标成表情段」后，又走到另一个极端：**群里发的表情包经常就是普通图片段**（`sub_type=0`），全被挡在外面。

中间试过「按尺寸猜」：近方形、边长 ≤ 600、≤ 512KB。这是个**代理指标**——它和「是不是表情包」没有因果关系：游戏截图同样小、同样近方、同样是普通图片段，而长条形的表情包会被误杀。

**决定**

1. 判定分三段，从便宜到贵：
   - 字节真是动图 → 收（不需要判断）
   - QQ 标成表情段（`sub_type` 1/7/11）→ 收（不需要判断）
   - **其余普通静态图 → 交给模型看图判断**（`op=judge`）
2. 模型只回一行 JSON `{"sticker":bool,"why":"…"}`，`maxTokens=60`，温度 0
3. **结果按 md5 缓存**在 `judge-cache.json`：同一张图重发不再花钱
4. 模型不可用（无 llm / 调用失败 / 输出看不懂）→ **退回按尺寸猜**，绝不因为判定失败就不收
5. 模块参数 `judgeMode`：`model`（默认）/ `size`（免费但会漏会错）/ `off`（不收普通图）

**理由**

- 表情包与截图的差别在**画面内容**，不在元数据。用元数据近似内容，注定在边界上出错。
- 这条判断每张图只做一次，且有 md5 缓存，成本随「新图数量」增长，不随「收图次数」增长。
- 兜底保留尺寸判断，是为了「模型挂了也别把功能停摆」——降级而不是失败。

**后果**

- 每张**没被 QQ 标记的静态图**会花一次视觉调用（约 ¥0.002/张）；重复图免费。
- 判定结果可审计：日志里会写 `这张不是表情包，不收（游戏组队界面截图）`。
- 尺寸闸门降级为「模型没结论时的兜底」，不再作为主判据。

## ADR-0021 · 峰谷节奏单独成模块，只挂 `group/decide`

**背景**

DeepSeek 按峰谷计价：工作日 09:00–12:00、14:00–18:00 是高峰（全价），其余时段和周末是空闲（半价）。用户希望**高峰少说话、空闲活跃一点**，把省下来的钱换成功率。

**决定**

1. 单独一个 Aurabot 模块 `peak-rhythm`（名字「峰谷节奏」），**不塞进表情模块、也不改人格**；
2. 唯一干预点：`group/decide`（群里「这条回不回」的最终决定）——
   - 高峰：本来要回 → 按 `peakKeep%` 压下来
   - 低谷：本来不回 → 按 `offpeakInterject%` 插一句
3. **私聊和被 @（`mode === 'must'`）一律不干预**：那是该回的话，省钱不能省掉基本响应；
4. 峰谷判断用 `dsh-meter`（计价插件）的同一套规则：工作日 9-12/14-18、Asia/Shanghai、周末全天算空闲；时段可在模块设置里改，但**节假日不认**（`dsh-meter` 认，这里没跟）；
5. 关掉开关 = 完全回到原逻辑，不影响任何别的东西。

**理由**

- 频率是聊天策略，跟表情库、人格都无关，混在一起以后谁都不敢改；
- `group/decide` 是官方给的"回不回"钩子，比在 `message` 里吞消息干净；
- 规则抄计价插件而不是自己发明，两处口径不会打架。

**后果**

- 高峰时群里明显安静；被 @ 和私聊不受影响。
- 每 5 小时左右的高峰窗口里，插话概率被压到 `peakKeep`（默认 20%）。
- `/峰谷` 命令能随时看当前状态与参数，便于确认"现在到底是峰还是谷"。
