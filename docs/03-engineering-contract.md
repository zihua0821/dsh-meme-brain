# 工程契约

> 本文是本项目的**强制约定**。任何实现如果与本文冲突，以本文为准。
> 前提：**维护者不阅读前端与宿主代码**，因此正确性不能依赖人工审阅，只能依赖结构与自动验证。

---

## 1. 五条保证

### G-1 · 界面永远不是唯一路径

**含义**：任何一项能力（浏览、筛选、改标注、合并重复、导入导出、重建索引），都必须存在不经过 Web 界面的操作方式。

**规则**
- 每个写操作对应一个命令或 HTTP 端点；
- 界面调用的就是这些端点，不允许界面直连数据库或独有逻辑；
- 若某个能力只有界面能做，视为缺陷。

**验证**：验收清单里每条功能都标注"命令路径"。缺一条即不通过。

---

### G-2 · 业务逻辑只在 Host，界面是薄视图

**含义**：界面不产生业务判断。

**界面只允许做三件事**
1. 取出宿主给的 JSON；
2. 渲染成 DOM；
3. 把用户操作变成一次请求，参数与原命令一致。

**界面明确禁止**
- 计算分数、判断重复、推导状态；
- 自己维护业务缓存（只允许临时 UI 状态：展开/选中）；
- 直接读写文件或数据库；
- 决定"要不要分析/要不要重试"。

**为什么**
前端 bug 的爆炸半径被限制为"显示不对"，永远到不了"数据坏了"。维护者不需要读前端代码即可接受风险。

---

### G-3 · 数据自证：`doctor` 是唯一巡检入口

**含义**：系统必须能自己报告健康状况，不需要人读代码或翻日志。

**`meme doctor` 必须输出以下各项**（数值正确性即系统正确性）

| 检查项 | 期望 | 不通过的处置 |
|---|---|---|
| schema 版本 | 等于代码期望值 | 提示需要迁移 |
| 库文件数 / 索引记录数 | 两者相等 | 列出差异 |
| 孤儿文件（有文件无记录） | 0 | 可一键补录 |
| 索引缺文件（有记录无文件） | 0 | 可一键清理 |
| 哈希可重算 | 抽样 N 张重算一致 | 报解析器问题 |
| 重复簇 | 列出数量与成员 | 交由人合并 |
| 未分析 / 低置信 / 失败 | 各队列数量 | 可进入处理 |
| 最近一次备份时间 | 存在且不早于上次迁移 | 提示备份 |

**规则**：`doctor` 只读，不自动修复；修复由单独命令执行（`repair --orphans` / `repair --missing`），两者的区别必须在输出中说清楚。

---

### G-4 · 不可逆操作都有退路

| 操作 | 退路 |
|---|---|
| 数据迁移 | 迁移前自动复制 `index.db` 到 `backups/`，文件名带时间戳 |
| 删除 | 软删除（标记 `retired`），`purge` 才是真删 |
| 合并重复 | 保留被合并方的记录与原图，可拆分 |
| 批量标注 | 记录操作历史，可撤销上一批 |
| 重建索引 | 不影响库文件 |

**规则**：任何会丢失信息的操作，必须先能导出该信息（`export`），或本身可逆。

---

### G-5 · 契约先行、版本化

| 对象 | 版本化方式 |
|---|---|
| cordis 服务 | `memeBrain.version`（整数，不兼容时递增） |
| 工具参数 | 在工具描述中固定；改名视为破坏性变更 |
| 数据库 | `schema_version` 表 + 迁移脚本 `migrations/NNN_*.js` |
| 配置 | zod schema 校验，缺失项用默认值，未知项忽略并告警 |
| HTTP | 所有响应含 `{ ok, data?, error? }`，`error.code` 稳定 |

**迁移规则**
1. 迁移只能向前，不写降级；
2. 每次迁移前自动备份；
3. 迁移必须可 `--dry-run`；
4. 迁移后自动跑一次 `doctor`，失败则回滚到备份。

## 2. 三条设计规则

### 规则一 · 命令先行

实现顺序固定为：**数据层 → 命令 → 工具 → 界面**。

- 数据层（存储 + 索引）先能在测试里跑；
- 命令是第一种可用入口，也是验收的基准；
- 工具是命令的另一种外壳（同一函数）；
- 界面最后做，只调用命令对应的端点。

### 规则二 · 一个能力一份实现

同一个能力（如"按角色筛选"）只允许存在一份业务实现。命令、工具、HTTP、界面全部调用它。

禁止：界面里再写一遍筛选逻辑；工具里再算一遍判重。

### 规则三 · 失败要可数

任何失败都必须落到一个稳定错误码，并计入 `doctor` 的队列统计。

```
E_PARSE_UNSUPPORTED     格式不支持（如 WebP）
E_PARSE_CORRUPT         文件损坏
E_DEDUPE_BLOCKED        判重拦截（非错误，但计数）
E_STORE_WRITE           写库失败
E_ANALYZE_MODEL         模型调用失败
E_ANALYZE_PARSE         模型输出无法解析
E_DB_MIGRATE            迁移失败
E_LIB_MISSING           库目录不存在
```

## 3. 变更验证流程

每次改动（无论谁改、改哪层）都必须走完：

| 步 | 动作 | 通过条件 |
|---|---|---|
| 1 | 跑单元测试 | 全绿 |
| 2 | 跑离线回归（固定夹具） | 判重、解析结果与基线一致 |
| 3 | 跑 `doctor` | 除已知待办外无异常 |
| 4 | 若改了 schema | 在副本上 `migrate --dry-run` → 实跑 → `doctor` |
| 5 | 若改了界面 | 命令路径仍可用（证明界面不是唯一路径） |

**夹具（fixture）要求**
测试用的小图库放在 `test/fixtures/`，包含：
- 1 组已知重复（`摆烂摊手` 与 `摆烂式`）
- 1 组同模板不同内容（熊猫头系列）
- 1 张带透明 GIF
- 1 张静态 GIF（扩展名 `.gif`、字节是 JPEG）
- 1 张 PNG、1 张 JPEG
- 1 张损坏文件

固定夹具保证"改了算法能立刻看出回归"。

## 4. 代码组织约束

| 层 | 目录 | 允许依赖 |
|---|---|---|
| 解析/哈希 | `src/lib/parse.js`, `src/lib/dhash.js` | 仅解码库，无 I/O |
| 存储 | `src/lib/store.js` | 文件系统 + SQLite |
| 索引/检索 | `src/lib/index.js` | store |
| 业务编排 | `src/lib/pipeline.js` | 以上全部 |
| 入口 | `src/index.js`（Host）、`src/client.js`（Web） | 调用 pipeline / HTTP |
| 命令与工具 | `src/commands.js`, `src/tools.js` | 调用 pipeline，**不含逻辑** |

**规则**：`src/client.js` 不允许 import 任何 `src/lib/*`，它只能通过 HTTP/宿主接口取数据。这条从物理上保证 G-2。

---

## 5. 测试分层

| 层 | 方式 | 频率 |
|---|---|---|
| 单元 | `node --test test/unit/*.test.js` | 每次改动 |
| 回归 | `node --test test/regression/*.test.js`（用固定夹具） | 每次改动 |
| 集成 | `npm run verify`（临时库 + 真实 SQLite） | 每次改动 |
| 自检 | `meme doctor` | 每次部署 / 每日 |

## 6. 维护者操作手册（不需要读代码）

| 我想知道 | 做什么 |
|---|---|
| 系统还好吗 | `meme doctor` |
| 为什么这张没进库 | `meme explain <md5|路径>` → 输出该图经过每个阶段的结果与错误码 |
| 判重太严/太松 | 改配置 `dedupe.threshold*`，然后 `meme doctor --dedupe` 看受影响对数 |
| 索引坏了 | `meme rebuild --index` |
| 想换机器 | `meme export --all` → 新机器 `meme import` |
| 某次改动是否安全 | 走 §3 的五步 |

**`meme explain` 是这套契约的关键补充**：它把"这张图为什么没出现"变成一条可读的时间线（接入→解析→判重→入库→分析），每一步给出结论与错误码。有了它，维护者不需要读代码就能定位问题。

---

## 7. 本文的维护

- 新增能力 → 检查是否符合 G-1/G-2；
- 新增数据结构 → 检查是否满足可重建（ADR-0003）；
- 新增不可逆操作 → 必须补退路（G-4）；
- 每次发布前确认 `doctor` 能覆盖新领域的健康检查。
